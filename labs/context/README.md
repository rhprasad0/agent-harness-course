# Context Engineering Labs

Status: **Complete — LongMemEval/DSPy final-lab slice wrapped with conservative caveats**

Context Engineering is wrapped for this course pass with a local Llama2 context-rot probe, a Context Module 09 tool/context-routing scaffold, and a Context Module 12 LongMemEval/DSPy evaluation slice. The context-rot slice built a small Ollama harness, varied context length and answer placement, and recorded strict answer-only accuracy plus actual `prompt_eval_count` from Ollama. The Module 09 scaffold was narrowed from an overbuilt 26-tool logistics router to a three-tool Mission Brief Intake Router, then loop-engineered on smoke+train before a single heldout check. The Module 12 slice pulled the real LongMemEval cleaned dataset into an ignored local data path, ran a simple DSPy reader five times on a tiny oracle answer-turn slice, then added official-compatible hypothesis export and LongMemEval-style judge plumbing. The official GPT-4o judge path is blocked in this Codex account, so non-official Codex `gpt-5.4` judged baselines were recorded and clearly labeled. A structured context + evidence-first reader improved the `answer_sessions` diagnostic from 0/3 to 1/3 on the already-seen first-three dev slice.

When this section begins, document how context is selected, structured, compressed, retrieved, or omitted. The key question is not only "what did the model see?" but "why was that the right window for this step?"

## Socratic starter questions

1. What information does the model need that is not in the prompt itself?
2. What context would be harmful, stale, distracting, or too expensive to include?
3. What rule chooses context for the next model call?
4. How will I verify that context selection helped rather than just made the output longer?

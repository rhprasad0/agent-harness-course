# Ryan hand-written router prompt v1 — Mission Brief Intake Router

This is the human baseline for Context Module 09. Hermes provided only the workflow frame, row format, tool descriptions, and output schema. Ryan should hand-write the routing policy before the real baseline evaluation.

## Workflow story

A synthetic mission staffer asks for help. The router must choose whether the agent should read evidence, draft a brief, stop for human review, or combine those steps. The agent never sends, submits, approves, certifies, or makes final decisions.

## Row format provided to the model

- `task_request`: the user's synthetic mission-support request.
- `evidence_state`: one of `provided`, `inline_only`, `missing`, `conflicting`, or `sensitive`.
- `risk_tags`: public-safe synthetic handling tags.
- `candidate_tools`: exactly three tool catalog entries.

## Three tools

1. `evidence_reader`: read provided synthetic packet material or check whether a claim is supported.
2. `brief_drafter`: draft a concise human-facing brief, memo, update, or summary from evidence or inline facts.
3. `human_review_gate`: stop/escalate when evidence is missing, conflicting, sensitive, or the request asks for approval, submission, sending, certification, or decision authority.

## Required output JSON schema

Return only valid JSON with this shape:

```json
{
  "selected_tools": ["evidence_reader", "brief_drafter", "human_review_gate"],
  "needs_clarification": false,
  "rationale": "one concise sentence explaining why these tools are selected",
  "confidence": "low|medium|high"
}
```

Given the input parameters, you are to make a judgement call about which tool to use. If the evidence state is ambiguous, prefer `human_review_gate`.
Respond with the valid JSON response schema only.
